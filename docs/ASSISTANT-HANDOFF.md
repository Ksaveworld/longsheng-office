## 问题与改动

普通影响分析不一定生成模型 proposal。原先仅有 proposal 时才显示操作预览，用户看完分析后缺少清楚的办理入口。

- 助手成功取得回答并刷新当前状态后显示“下一步处理”，复用事项页 RoleAction、BusinessActions 和 TaskAction。
- 当前岗位、事项和数据版本在提问区域可见；下一步由既有业务规则决定，不依赖模型是否生成 proposal。
- 已有核验任务显示查看入口；有权限的岗位可开始处理、提交结果。等待他人或条件不齐时显示原因。核验通过后由负责人批准，采购/销售回执齐全后才能关闭。
- 从助手确认成功后返回同一事项，显示最新处理结果与下一步。原确认、取消、幂等和角色守卫保留。
- `/preview` 支持可选 `expectedVersion`。助手按回答版本准备操作，旧版本返回 409；非法版本返回 422。即使版本正确，仍检查岗位和业务前置条件。原调用方未传版本时保持兼容。
- 历史/过期回答、模型失败、状态刷新失败不开放回答关联写操作；保留查看任务、重新查询或重试入口。

## 验证

- 对应发布基线的 35 项办公测试通过，HTTP 测试补充旧分析版本、非法版本、正确版本但错误岗位的预览检查。
- TypeScript/Vite 构建与变更前端文件 ESLint 通过。
- `node scripts/verify-office-handoff.mjs`：独立临时数据库及浏览器，明确使用规则模式；验证首页入口、取消、旧分析、旧确认、重复点击、已有任务、无权限、四岗位主链、失败重试及 1440/1280/390px。
- 设置 `OFFICE_VERIFY_ENV` 为本机已有模型配置文件路径时，仅首个问题走真实模型，其后改为显式规则模式做确定性回归。真实普通分析未返回 proposal，办理入口仍出现；不得把其后规则测试描述为全流程真实模型评测。
- `OFFICE_VERIFY_OUT` 可指定截图与 JSON 报告目录；默认 `.runtime/handoff-verification`。不重置既有演示空间。

本次实现和验证不代表企业身份、多事项、真实资料或真实消息通道已接入。公网发布状态另行记录。
