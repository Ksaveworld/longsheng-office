## 对原判断的回测结论

“流程有逻辑，但页面需要持续说明状态和交接”的判断有依据。回测时，事项详情已增加办理摘要，但助手页仍把当前操作放在较下方；历史较长时需要寻找，资料页也缺少同样的上下文。另有非供应类案例仍使用笼统“确认发起”的文案。

本轮补齐：

1. 首页、事项详情、助手和业务依据共同使用同一状态解释，显示当前状态、我的任务和责任岗位。助手摘要固定在历史滚动区上方，长聊天不再挤走当前进度。
2. 供应延期及其他事件的核验均区分“准备核验申请 → 核对核验申请 → 提交给接收岗位”。提交后显示成功及当前无需操作，角色交接必须显式切换。
3. 读取失败标记旧记录并暂停办理。提交结果未知时保留原提交编号核对；已保存后的刷新失败不再被描述成提交失败。
4. 操作指南以任务和岗位交接为主线，验证与截图另附；历史说明保留其时间和范围。

## 重跑方式

按 README 使用 Node 24 安装依赖；浏览器脚本需要本机 Chrome。`npm run test:office` 和 `npm run build` 不需要真实模型密钥。

浏览器脚本针对本地 5198 测试服务，先执行 `node node_modules/vite/bin/vite.js build --outDir .runtime/representative-dist`，再以 `node scripts/preview-representatives.mjs --rules` 启动独立规则服务。运行 `node scripts/verify-journey-audit.mjs` 可复现补充检查；也可通过 `OFFICE_BASE_URL` 指向另一个获准的本地测试服务。

完整 `verify-representatives.mjs` 明确要求真实模型：在本地 `.env.model.local` 填入获准的 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`，以不带 `--rules` 的预览命令启动，再运行脚本。密钥文件不得提交。记录中的模型答案为一次实际测试，不保证所有未来模型请求产生完全相同文字。

测试自动新建独立合成会话，不需要重置用户数据。截图和 JSON 会更新本轮证据目录；复跑时应保留原报告或用新的日期目录区分结果。
