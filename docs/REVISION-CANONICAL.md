本次通过提交 `dd58bcc` 撤销 V2 修改，恢复到初版代码树，再按既定供应链异常响应方案调整。没有沿用被否决的 V3 评审样稿，也没有将旧数据库重置为初始数据。

业务范围保持为一次供应商延期的办公协同：查询影响、追溯会议决定、比较到料方案、质量核验、负责人确认、采购与销售执行、回执与事项关闭。继续使用两条订单、两家供应商、两份有先后关系的合成会议记录。

## 页面与操作

| 页面 | 本次行为 |
| --- | --- |
| 办公协同首页 | 显示延期提醒、订单影响与待处理动作。继续处理进入助手，仅预填问题，不自动发送；另有进入事项处理的入口 |
| 业务助手 | 查询影响、决定与最新进度；回答可打开来源或准备业务动作。没有必须完成三轮聊天才能办理的门槛 |
| 事项详情 | 当前情况、有效决定、等待岗位和本岗动作在上方。下方可查 A/B 比较、任务回执、会议原文和完整记录；全量关系图默认折叠 |
| 演示设置 | 配置模型、选择规则模式、修改场景变量、模拟发送失败、执行同题对比和重置当前空间 |

普通业务页面不展示演示步骤串联、流程讲稿或面向观众的系统说明。切换岗位时共享事实不变，本人操作随任务和授权条件变化。

- 核验由负责人或采购发起，只有质量负责人可提交核验结论。
- 任务接收人点击“开始处理”后直接开始；未开始时不同时显示提交结果按钮。
- 核验发起、核验结果、供应方案批准、部门回执和事项关闭保留预览与人工确认。
- 质量不通过时不能批准切换；重新发起沿用 `T-QA`，保留历史核验凭据。
- 负责人批准后形成新的有效决定，并创建采购、销售任务；专业结果由对应岗位提交。
- 采购、销售可以任意先后提交。已提交但尚未关闭时显示待复核，回执未齐不能关闭。
- 发送失败与业务完成分开表达。重试沿用原任务，每轮最多三次送达尝试，不创建重复任务。

## 沿用的能力与兼容处理

真实模型调用、SQLite 保存、来源追溯、人工确认和同题对比在此前版本已存在。本次调整页面入口与办理顺序，并修正任务状态及历史兼容处理，不将这些已有能力表述为新接入。

状态读取兼容旧任务与回执。旧核验重开后保留历史凭据，当前轮清理旧开始和送达时间；回放旧确认结果时重新生成相同状态对应的分析与关系图。业务写入继续检查角色、当前版本和幂等键。

模型调用失败不会自动变成规则回答；规则模式需要显式选择。同题对比仍使用同一问题、模型、状态版本和预算，不预设哪一侧获胜。
