# 龙盛办公协同 Demo｜按岗位完成一件事

你以业务负责人的演示身份收到 M-01 原料延期通知，需要判断哪些订单受影响，推动备选方案，并在交给其他岗位后跟进结果。供应商、订单及回执均为合成样例。

## 先认清四个入口

| 入口 | 来这里做什么 |
| --- | --- |
| 首页“办公协同” | 看四类代表场景、我的待办及等待其他岗位的事项；卡片打开事项详情 |
| 事项详情 | 固定办理中心；顶部先看当前状态、我的任务、当前责任岗位，再执行动作 |
| 业务助手 | 询问影响和依据；顶部摘要显示当前进度，聊天是历史问答，办理回到事项详情 |
| 业务依据 | 核对来源、会议决定和关联对象；需要时展开原始记录 |

首页保留 SUP-001／M-01 供应延期、SUP-007 质量批次异常、SUP-008 客户订单需求变更、SUP-009 设备检修影响排产各一例。M-01 的两张订单、A／B 供应商和部门任务属于同一条链路。

## 一次完整演示

在首页打开 M-01 卡片。每次操作后，先读事项顶部；看到“你当前无需操作”就表示当前岗位这一段已结束。只有要演示下一岗位时，才点击明确的岗位切换按钮，或使用页顶“当前岗位”。

| 当前角色 | 操作 | 怎样判断成功 | 接下来轮到谁 |
| --- | --- | --- | --- |
| 业务负责人 | 进入 M-01，点击“询问影响与依据”，询问这次延期影响哪些订单、当前决定是什么 | 回答与订单条件卡可核对，来源能打开；当前采用 A | 业务负责人判断备选方案 |
| 业务负责人 | 回到事项详情，“比较并选择方案”，选择 B 版本并“确认选择” | 顶部显示已选版本；仅保存选择，不代表核验或批准 | 业务负责人准备申请 |
| 业务负责人 | “准备核验申请”，核对事项、版本和接收岗位，再“提交给质量负责人” | 显示“核验申请已提交”“等待质量负责人接收”“你当前无需操作”；当前仍采用 A | 质量负责人 |
| 质量负责人 | 显式切换岗位，“接收核验申请”并确认，再“开始核验” | 状态依次显示待开始、核验中；接收不等于通过 | 质量负责人 |
| 质量负责人 | “提交方案核验结论”，选择结论、填写核验凭据，检查并确认提交 | 通过后等待业务负责人批准，当前仍采用 A；不通过则回到补齐依据或重选 | 业务负责人 |
| 业务负责人 | 显式切回，“批准切换至 B”并“确认批准” | 当前采用 B；部门任务仍待发送 | 业务负责人 |
| 业务负责人 | “确认并发送部门任务”并“确认发送” | 采购和销售出现待接收任务；发送不等于部门办完 | 采购经办、销售经办 |
| 采购经办 | 接收、开始处理、提交处理回执；填写供应安排与待补凭据 | 回执保存；销售尚未完成时仍不能关闭事项 | 销售经办／业务负责人 |
| 销售经办 | 接收、开始处理；选择相关订单，填写沟通内容和结果，提交回执 | 两个部门均有回执后，负责人出现关闭动作 | 业务负责人 |
| 业务负责人 | “复核回执并关闭事项”并确认 | 显示“办公协同已办结”；首页已办结数量更新，仍保留此代表事项 | 本次办公协同结束 |

岗位切换是演示身份。任务发送发生在 Demo 内部，办公办结不表示原料已实际到货或订单已交付。

## 可选：演示日期变化后的影响

需要展示延期由 D6 变为 D9 时，在办理开始前打开“业务依据”，导入仓库 `public/supply-samples/Supplier.csv` 和 `Order.csv`，先预览、再确认。已进入办理流程后不再覆盖导入。

向助手提问：“筛选当前有到料风险且至少晚 2 天的订单，统计数量并引用导入记录。”此样例应命中 ORD-001-01 一条，预计晚 4 天；ORD-001-02 预计晚 1 天，不满足“至少晚 2 天”。打开来源可核对 CSV 原始行。日期计算为到料影响，不等于成品交付延期或违约。

## 遇到异常时

- 准备页点击“取消”不会提交申请；不要把打开核对页当成已经提交。
- 显示“暂时无法确认提交结果”时，用“核对提交结果”检查原提交。系统沿用同一提交编号，避免重复申请。
- 提示“事项已更新”时，重新检查最新版本后再确认；旧核验不能代替新版本核验。
- 显示“暂时无法确认最新进度”时，页面保留上次读取的记录并暂停办理；点击“刷新数据”恢复后继续。
- 打开旧重复案例链接时，使用“打开代表事项”进入 M-01；历史数据没有改名为新案例。
