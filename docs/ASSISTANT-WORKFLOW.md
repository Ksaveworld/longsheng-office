# 助手完整办理与事项回顾：实施计划

2026-09-09，用户已授权实施。基线 `4a17c7a`。本次更新取代上一轮“助手确认后自动返回事项”的交互；历史验收文档保留。

## 已确认范围

1. 八步在业务助手中完整呈现和办理：延期通知、影响分析、会议决定、方案比较与选择、质量核验、负责人确认、采购销售执行、回执与最终复核关闭。
2. 模型回答与当前业务状态分别展示：旧回答保持原文并标识版本；新的岗位任务直接依据最新状态办理，不强制每个岗位重问模型。
3. 助手内展示 A/B 比较，显式选择并记录原因；选择不等于批准。B 需质量核验和负责人批准。用户已确认 A 分支：负责人确认沿用 A 后，采购和销售提交跟进回执，负责人复核关闭办公事项；到料风险继续保留。
4. 操作成功后留在助手，更新下一责任人和任务；所有写入沿用人工确认、角色、版本与幂等校验。
5. 从事项回到助手保留当前问答、草稿、失败重试与查询状态，按空间、事项、岗位、模式隔离；运行中切页不丢结果。历史模型建议不能恢复成可执行的新批准。
6. 事项详情为全过程回顾：事由、影响、原会议、选择原因、批准、质量依据、任务回执与最终复核，不再承载独立办理入口，不生成简报文件。
7. 最终复核在助手及确认抽屉中直接呈现两份回执、提交人和时间、当前决定与遗留风险；负责人明确确认后关闭，并保存复核记录。

- 后端子任务：选择/沿用 A/关闭记录、模型和来源联动、领域测试。

- 主代理：状态接口整合、助手会话保存、方案交互、事项回顾、确认流程、计划更新、构建及浏览器验收。

## 验收

- A、B 各自用四岗位完成适用链路；A 不伪造 B 核验，风险不因关闭消失。
- 从首页进入助手后，选择、核验、批准、回执、关闭都无需跳到事项办理。
- 采购和销售回执顺序不限；一份时不可关闭，齐全后负责人实际看见凭据再确认。
- 查看事项后返回、浏览器前进后退、运行中切页、不同岗位来回切换均保留正确会话；刷新可从当前岗位历史恢复回答，旧依据写操作保持禁用。
- 取消不写入；重复点击不重复任务；旧预览、角色错误、缺证据、质量拒绝、发送失败和重试上限继续受控。
- 兼容原有开放、核验中、已批准及已关闭空间，不重置用户数据。检查桌面与手机宽度。
- 实跑真实模型验证回答与资料、A/B规则和操作衔接；确定性浏览器回归明确使用规则模式。
