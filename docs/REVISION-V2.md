# 办公协同 Demo 第二版修改方案

本版依据《龙盛集团供应链异常响应 POC 方案》和《浙江龙盛 Demo 现有代码修改方案》统一实现。保留原浅色界面、爱化身标识、四个页面、合成业务样例和真实后端。

## 本版取舍

两份材料中不一致的交互细节，以具体代码修改说明为准：

| 分歧 | 本版行为 |
| --- | --- |
| 首页是否提前分析 | 初始为待分析；点击后进入助手并实际分析，成功才展示结果 |
| 点击入口是否自动发送 | 明确点击“分析影响”即发起第一轮；普通自由提问仍由用户发送 |
| 候选方案编号 | 保留 DEC-02，显示“附条件候选方案 · 未生效” |
| 发送失败是否进入默认演示 | 默认关闭，在演示设置中主动开启 |
| 同题对比位置 | 演示设置 → 演示复盘 |
| 全量关系图位置 | 演示设置 → 技术视图；事项详情保留简化业务关系 |

## 流程与页面

事项依次进入 S0 待分析、S1 处理中、S2 待质量核验、S3 待负责人确认、S4 执行中、S5 待复核、S6 已完成。S5 从收到首份部门回执开始，缺少其余回执时列出关闭条件，全部满足后才允许复核关闭。质量拒绝返回 S1，保留任务和凭据历史。

首页回答“发生了什么、现在轮到谁、下一步是什么”。初始角色为业务负责人。影响分析、会议追溯和到料处置路径比较在助手依序进行；发起质量核验前必须完成这三步。质量、采购、销售在首页处理当前任务；负责人在首页批准或最终复核。详情为事项档案，不重复提供高优先级执行按钮。

助手左侧显示结构化业务事实、实际模型回答与来源，右侧为当前事项上下文。模型名称、参数、耗时和工具记录默认折叠。每次运行保留所用数据版本；历史回答不冒充当前事实。

事项详情默认处理进展，其余标签为影响与条件、决定沿革、来源资料、业务关系。设置分为场景变量、模型运行、技术视图、演示复盘。

## 执行与数据约束

- 事项进展、任务工作状态和消息发送状态分别表达；发送成功不代表完成任务。
- 待处理动作计数覆盖任务、重试、待批准与最终复核，不重复计算同一任务。
- 关键动作使用对应内容的确认抽屉；取消不写入，旧版本预览不能继续提交。
- 质量未通过不得切换 B；负责人未批准不得创建采购、销售任务。
- 导航、刷新、角色切换和服务重启继续读取同一空间；旧空间数据保留并兼容升级。
- 模型失败明确显示失败，不推进分析阶段、不伪造回答；规则模式由用户明确选择。
- 更新沿用现有线上入口和访问码；发布前保存旧镜像与数据备份，以便回退。

## 验收

验证 S0–S6 完整主线、质量拒绝、发送失败与原任务重试、重复确认、版本变化拦截、刷新与重启持久化、真实模型和同题对比，以及移动端四页。真实 DataOS、OA、ERP、企业身份和消息通道仍未接入；本轮完成的是办公协同 Demo。
